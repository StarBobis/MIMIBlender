# 修复无法正确读取贴图的问题

## 问题描述

在使用插件时，如果用户在 Shader Editor（着色器编辑器）中修改了材质，例如：
- 替换了贴图节点。
- 使用 Node Wrangler (Ctrl+Shift+Click) 预览了某个中间节点。
- 断开了某些节点的连接。

点击 "Update Material List" 后，可能会出现以下异常：
1. **贴图尺寸错误**：识别到的贴图大小变为 32x32 像素（这是 Blender 默认的空纹理或 Viewer 节点占位符的大小）。
2. **合并失败**：这些材质在合并时被忽略，或者合并出来的结果是错误的颜色。

## 原因分析

### 1. Blender 的材质输出机制
一个材质中可以有多个“输出节点”（Output Node）。
- **正常输出**：`Material Output`，用于最终渲染。
- **预览输出**：当你使用 Node Wrangler 预览时，它会创建一个临时的 `Viewer Output` 节点。

### 2. 旧代码的缺陷
原有的代码在寻找“哪个是最终输出节点”时，逻辑过于简单：
```python
# 旧代码逻辑
for node in nodes:
    if node.bl_idname == "ShaderNodeOutputMaterial":
        return node  # 找到第一个就直接返回！
```
它只是简单地遍历所有节点，返回它找到的**第一个**输出节点。
- 如果你用了 Node Wrangler，材质里会有两个输出节点。
- 代码可能会错误地抓取到 `Viewer Output`（预览节点）或者一个被断开连接的旧节点。
- 如果抓取到了断开的节点，插件就追踪不到前面的贴图，导致读取失败（返回默认的 32x32 占位符）。

## 修复方案

我们修改了 `utils/materials.py` 中的 `_find_output_node` 函数，让它变得更聪明。现在它会按照优先级来寻找正确的节点：

### 新的查找优先级

1.  **优先级 1（最佳）**：既是**当前活动（Active）**的，又有**连线（Connected）**的输出节点。
    *   *这是最理想的情况，代表用户当前选中的、且正在生效的那个输出。*

2.  **优先级 2（次佳）**：任何有**连线**的输出节点。
    *   *如果活动节点没连线（比如用户误操作断开了），我们就找另一个连着的节点，保证能读到数据。*

3.  **优先级 3（保底）**：**当前活动**的输出节点（即使没连线）。
    *   *如果所有节点都没连线，至少返回用户选中的那个。*

4.  **优先级 4（最后尝试）**：任意一个输出节点。

### 代码对比

**修改前：**
```python
def _find_output_node(nodes):
    for node in nodes:
        if node.bl_idname == "ShaderNodeOutputMaterial":
            return node  # 只要是输出节点就返回，不管有没有连线
    return None
```

**修改后：**
```python
def _find_output_node(nodes):
    # 1. 优先找：既是活动节点，又有连线的
    for node in nodes:
        if (node.bl_idname == "ShaderNodeOutputMaterial" and 
            node.is_active_output and 
            node.inputs[0].is_linked):
            return node

    # 2. 其次找：只要有连线的
    for node in nodes:
        if (node.bl_idname == "ShaderNodeOutputMaterial" and 
            node.inputs[0].is_linked):
            return node
            
    # ... (后续保底逻辑)
```

## 总结
这个修复确保了插件总是能找到**真正正在起作用**的那个材质输出节点，从而顺藤摸瓜找到正确的贴图文件，解决了贴图识别为 32x32 或合并丢失的问题。
