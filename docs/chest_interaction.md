# 胸部交互乳摇系统

使用永劫无间预设，在蓝图中添加“胸部交互乳摇系统”，保留原有输出连线。

1. 区域对象选择已经接入输出的身体网格。
2. 已有胸部骨骼组时，选择来源顶点组，点击“复制权重到此区域”。原骨骼组保留；系统创建专用控制组。
3. 添加第二个区域并重复操作。当前最多两个区域。没有现成权重时，在编辑模式选择顶点，使用“从选中顶点创建区域”；工具向选区外羽化。
4. 指定包含当前身体 IB 的 FrameAnalysis 目录，点击“从捕获自动配置拾取”。留空时查找当前预设目录中最新捕获。无法确定唯一候选时显示错误，允许高级用户填写 VS/PS。
5. 调整最大拉伸幅度、回弹速度和阻尼，然后正常导出。游戏中按 Alt + 鼠标左键拖拽；松手回弹。Ctrl + Alt + D 切换启用状态。

权重应在边缘渐变；常量权重、空组、缺失组不能提供有效区域。复制的数字骨骼组不会被改名或删除。专用控制权重在导出临时网格上采样并剥离，不参与骨骼权重归一化。

## 实现与边界

`resources/interaction/drag` 保留用户提供的“胡桃睡衣透视”Mod 的拾取、弹簧、形变及调试 shader；`runtime.ini` 将对应 INI 的角色标识、绘制范围、资源长度、shader 标识和参数替换为模板占位符，不包含参考角色的网格或贴图。

`common/interaction/drag.py` 为当前导出的每个可见 drawindexed 范围实例化拾取命令，保留原有显隐条件。使用当前 submesh 实际导出的索引缓冲及全局顶点索引。状态每帧最多积分一次；松手归零目标并保留阻尼回弹；位置每次从不可变 rest buffer 计算。拾取使用原生 VS 的投影、32 个输出寄存器变体、场景深度比较及实时 GS/HS/DS/输出目标守卫。

这是每区域共享位移的程序化形变与弹簧回弹，不是软体碰撞或布料求解。当前拖拽导出限定 Naraka 的 40 字节 Position 布局；受影响 DrawIB 含跨 IB 转移、实例化绘制、形态键或其他位置写入者时，需另行适配，不宣称已经兼容。固定拉伸路径保留给旧文件。

自动选择器要求目标 IB 的唯一 shader 对对应单个 R16G16B16A16_FLOAT 输出且日志记录绑定深度；支持 DDS 的 DX10 格式 10 和 legacy FourCC 113。此条件只选候选通道；真正运行仍依赖实时守卫。场景深度遮挡、特殊材质、角色动画、视角切换与游戏更新后的观感需要游戏实测。

## 验证

- `python tools/test_interaction_drag.py`：两个绘制范围、64 条 GS 绘制声明、资源引用闭合、缓冲长度、shader 文件、两种 DDS 头与多目标通道拒绝。
- 现有 `tools/test_interaction_export.py`、`tools/test_interaction_export_conflicts.py`、`tools/test_interaction_deformation_math.py`、`tools/test_interaction_weight_field.py`：固定路径回归、权重与形变数学。
- 使用 Windows SDK `fxc /T <stage>_5_0 /E main` 编译所有 37 份 shader；输出放 `tmp/`。
- 2026-11-17 通过当前 Blender MCP 将组 11/12 复制为两个控制组，逐点比较一致；使用用户指定捕获 `FrameAnalysis-2026-11-17-170451` 自动选择 VS `f77e3e6d280571ec` / PS `3ef340e7c7dfb4f2`，将当前模型实际导出到 `tmp/live_drag_export`。这不等于游戏运行时验收，也未进行对抗审查。

开发热刷新时，用 `type(live_node)` 找到实际注册的类，动态补充 RNA 属性并替换 draw 方法，避免注销节点导致用户数据丢失。安装目录可能是指向源码的 Junction，复制前需比较解析路径；同文件复制会在 Windows 报文件占用。未保存场景应先保存副本至 `tmp/`，保留原会话文件名。
