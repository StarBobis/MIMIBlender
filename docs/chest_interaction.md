# 胸部交互乳摇系统-永劫无间专用

使用永劫无间预设，在蓝图中添加“胸部交互乳摇系统-永劫无间专用”，保留原有输出连线。其他预设的添加菜单不提供此节点。

1. 区域对象选择已经接入输出的身体网格。
2. 直接在“胸部顶点组”中选择身体已有的组，例如当前模型的 `11`。无需创建或复制其他组。
3. 添加第二个区域并选择另一个胸部组，例如 `12`。当前最多两个区域；区域边缘的平滑程度来自所选组的实际权重。
4. 默认启用“自动使用 MMT 最新捕获”，导出时读取 MMT 当前游戏安装目录并匹配所选 Submesh 的拾取通道，无需填写路径或 VS/PS。“读取 MMT 最新捕获并配置”按钮可立即刷新。取消自动捕获后可自行选择目录并重新识别；高级设置中的“手动指定 VS/PS”允许覆盖自动匹配，手动值不会被刷新按钮改写。
5. 调整最大拉伸幅度、回弹速度和阻尼，然后正常导出。游戏中按 Alt + 鼠标左键拖拽；松手回弹。Ctrl + Alt + D 切换启用状态。

“显示交互调试信息”位于节点上方，默认关闭；控制游戏里的状态条、鼠标准星及诊断数字。修改后需重新导出，再在游戏里按 F10 重载。关闭只隐藏 HUD，拾取、拖拽与回弹继续工作。

状态条改为中文“按键、形变、绘制、通道、位置、拾取”，保留绿色/灰色状态；下面显示“拖拽”。出现通道或位置签名故障时，诊断区显示“实际、预期、槽位”。中文字形预烘焙为 shader 中的 32×16 位图，不依赖游戏字体接口。`python tools/build_interaction_hud_glyphs.py` 可从本机微软雅黑重建字形及 `tmp/interaction_hud_labels.png` 预览；已提交的 shader 可直接导出，运行时无需 Pillow。

权重应在边缘渐变；常量权重、空组、缺失组不能提供有效区域。原有骨骼组不会被改名或删除。每次导出直接读取当前所选组的最新权重，内部仅在临时网格上生成独立权重字段，采样后剥离，不参与骨骼权重归一化；不会在用户模型上新增组。

## 实现与边界

`resources/interaction/drag` 保留用户提供的“胡桃睡衣透视”Mod 的拾取、弹簧、形变及调试 shader；`runtime.ini` 将对应 INI 的角色标识、绘制范围、资源长度、shader 标识和参数替换为模板占位符，不包含参考角色的网格或贴图。

`common/interaction/drag.py` 为当前导出的每个可见 drawindexed 范围实例化拾取命令，保留原有显隐条件。使用当前 submesh 实际导出的索引缓冲及全局顶点索引。状态每帧最多积分一次；松手归零目标并保留阻尼回弹；位置每次从不可变 rest buffer 计算。拾取使用原生 VS 的投影、32 个输出寄存器变体、场景深度比较及实时 GS/HS/DS/输出目标守卫。

直接选组通过 `collector.configure_source_groups` 配置当前输出作用域，`stage_source_groups` 在单对象临时副本上快照权重。内部字段名由对象和来源组共同确定，防止合并不同对象时混用；`region_group_name` 保持导出配置与采样字段一致。旧文件的专用组配置继续作为兼容后备，界面不再展示该概念，也不自动删除用户已有组。后台 Blender 回归覆盖来源对象不新增组、再次导出读取修改后的权重，以及之前的归一化塌陷问题。

这是每区域共享位移的程序化形变与弹簧回弹，不是软体碰撞或布料求解。当前拖拽导出限定 Naraka 的 40 字节 Position 布局；受影响 DrawIB 含跨 IB 转移、实例化绘制、形态键或其他位置写入者时，需另行适配，不宣称已经兼容。固定拉伸路径保留给旧文件。

自动选择器要求目标 IB 的唯一 shader 对对应单个 R16G16B16A16_FLOAT 输出且日志记录绑定深度；支持 DDS 的 DX10 格式 10 和 legacy FourCC 113。此条件只选候选通道；真正运行仍依赖实时守卫。场景深度遮挡、特殊材质、角色动画、视角切换与游戏更新后的观感需要游戏实测。

自动目录依据 MMT 的 `Games/<game>/Config.json` 中 `installDir`，结合当前工作区 `Config/FrameAnalysisPath.json` 的外部路径和对象 LOD 范围寻找最新完整捕获；工作区旧格式路径继续兼容。蓝图的对象/Submesh 绑定优先于对象名称，来源 JSON 的索引范围用于约束绘制候选。捕获来自正在运行的 Mod 时，IB 文件 hash 可能已被替换，顶部 DDS 也可能只是零字节占位；解析器根据日志中的原始 IASetIndexBuffer、DrawIndexed 和 deduped 目标恢复证据，不把占位文件当作实际资源。无法唯一识别时提示处理，不静默猜测。

## 贴图槽位回归排查

2026-11-17 用户报告胸部变黑。对照更新前后的输出发现：旧版以 hash `6339b684` 替换贴图，新版从工作区读取的标记却是 `MarkType=Slot / MarkSlot=ps-t0`。同一捕获的 draw 130 文件名显示主通道 `ps-t0` 是 `.buf`，该 DiffuseMap hash 出现在 `ps-t8`。旧输出贴图与新导出的来源贴图 SHA256 也不同，因此不能只调整槽号而忽略原替换内容。

本次修复保留原替换贴图到工作区 `texture_overrides/chest_diffuse.dds`，将该工作区标记修正为 Hash 并记录观测槽位 `ps-t8`，在当前蓝图中通过全局 Hash 贴图节点显式选择原替换图。重新导出确认 hash 替换存在、错误的 `ps-t0` 赋值消失、实际替换图与旧输出字节一致。游戏内颜色恢复仍需用户重载后确认。

`capture.validate_texture_slots` 现在只对所选 IB、VS、PS 对应的捕获绘制记录检查：若 Slot/SharedSlot 标记指向明确导出为 `.buf` 的 PS 输入，拒绝该拖拽导出，不擅自猜测新槽位或改变用户贴图策略。对应回归检查包含缓冲区槽位拒绝以及 Hash 标记放行。

后续功能验证应先比较原生成 Mod 的显式贴图绑定与已编辑贴图内容，再比较新导出；所有文件路径存在并不能证明贴图替换与原输出等价。

## 胸部单点塌陷：归一化顺序

用户后续提供 `FrameAnalysis-2026-11-17-173730`。该捕获 draw 24 的日志将 `cs-t1` 关联到 `deduped/f0ecb4e2.buf`、`u0` 关联到 `deduped/1bdb163f.buf`、`cs-cb0` 关联到 `deduped/c37539a8.buf`。顶层零长度占位文件不能直接作为缓冲内容，须按日志追踪 deduped。

实测：输出缓冲 326720 字节，即 8168 个 40 字节顶点；上限 CB 为 `[8168,0,8168,0]`；索引最大值 8167。导出顶点 630 的四个蒙皮权重全零，运行时输出位置也为 `(0,0,0)`。其对应源网格顶点 625 原本是骨骼组 `12` 权重 1，同时交互控制组权重 1。这个样本的塌陷不能归因于容量不足。

原顺序是在复制单个对象后先运行 Blender Normalize All，随后在合并网格预处理器中采样并删除控制组。Normalize All 默认锁定活动组；活动交互组权重为 1 时，会把其他骨骼权重归一化为 0。后续再移除控制组，就留下了全零蒙皮权重。参考 Mod 的 GPU 链路无法修复上游已经损坏的骨骼数据。

修正后，带控制组的临时对象推迟归一化，先在合并网格上采样并移除控制组，再归一化骨骼权重；交互关闭时仍移除控制组，只跳过采样，避免控制组变成骨骼影响。源对象始终不变。当前真实导出保持 8168 顶点，全部权重和约为 1，顶点 630 恢复为骨骼 `12` 权重 1。

验证：`tools/test_interaction_skin_normalization_blender.py` 在独立后台 Blender 中覆盖活动控制组权重 1、邻接混合权重、交互启用和关闭；现有 modifier 与拖拽资源图回归通过。另将实际导出的 apply shader、Rest、Controls、State 放进 D3D11 WARP 回读，未拖拽时全部 8168 个顶点的 40 字节输出与 Rest 完全一致。用户重载修正版后的游戏观感仍需确认；以上未进行对抗审查。
